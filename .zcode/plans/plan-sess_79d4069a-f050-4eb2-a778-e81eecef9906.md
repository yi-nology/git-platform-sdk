## Work Stream 2: GoGit Backend — Expand Stubbed Operations

### Task 2.1 — Expand `GetConfig`/`SetConfig` to support arbitrary keys

**File:** `gitbackend/gogit_stash_config.go`

go-git/v5 supports arbitrary config via `cfg.Raw.Section(name).Subsection(sub).Option(key)`. Replace the current user.name/email-only logic with full generic config access:

- Parse `key` as `section.subsection.option` (3-part) or `section.option` (2-part)
- Use `cfg.Raw.Section(section).Subsection(subsection).Option(option)` for reads
- Use `cfg.Raw.Section(section).Subsection(subsection).SetOption(option, value)` for writes
- Call `repo.Storer.SetConfig(cfg)` to persist

### Task 2.2 — Implement stash operations using go-git plumbing

**File:** `gitbackend/gogit_stash_config.go`

go-git has no stash support, but we can implement it using low-level object manipulation:

**StashSave:**
1. Get current HEAD commit and worktree status
2. Create a tree from the current index state
3. Create a commit with 3 parents: HEAD, index tree, untracked tree
4. Write to `refs/stash`
5. Reset working tree to HEAD

**StashList:**
1. Walk `refs/stash` and `refs/stash@{N}` refs
2. Parse commit messages into `[]StashEntry`

**StashApply/StashPop:**
1. Read the stash commit at the given index
2. Cherry-pick the stash commit's changes onto the current working tree
3. For Pop, also drop the stash entry after applying

**StashDrop:**
1. Remove the stash entry at the given index by shifting remaining entries

**StashClear:**
1. Delete `refs/stash` and all `refs/stash@{N}` refs

### Task 2.3 — Implement `Rebase` using cherry-pick iteration

**File:** `gitbackend/gogit_commit.go`

The existing `CherryPick` method already works. Implement rebase as:
1. Find merge-base of current branch and `onto`
2. Get list of commits from merge-base to current HEAD
3. Move HEAD to `onto`
4. Cherry-pick each commit in order (using existing `CherryPick`)
5. If any cherry-pick fails with conflict, return `ErrMergeConflict`

**RebaseAbort:** Reset to the pre-rebase state (stored in a ref or backup)
**RebaseContinue:** Skip the conflicting commit and continue cherry-picking

### Task 2.4 — Implement non-fast-forward `Merge`

**File:** `gitbackend/gogit_commit.go`

Implement three-way merge using go-git plumbing:
1. Find merge-base using existing `MergeBase` from `gogit_status.go`
2. Get base, HEAD, and branch trees
3. Compute a merged tree using `object.DiffTree` on both sides
4. If both sides modify the same file, detect conflict and return `ErrMergeConflict`
5. Otherwise, write the merged tree and create a merge commit with two parents
6. Support `MergeOptions`: Squash (single parent), NoCommit (don't commit), Message, AllowUnrelated

### Task 2.5 — Keep `RunRaw` as stub but improve semantics

**File:** `gitbackend/gogit_core.go`

`RunRaw` is fundamentally incompatible with a pure-Go backend (it runs arbitrary git CLI commands). Keep it as a stub but add documentation explaining this is by design. No code change needed beyond perhaps a clearer comment.

### Task 2.6 — Populate `FetchResult` and `PushResult`

**Files:** `gitbackend/gogit_core.go`

**Fetch:**
1. Before fetch: list all remote refs via `repo.References()`
2. Perform the fetch
3. After fetch: list remote refs again
4. Diff the two sets to populate `FetchedRefs`, `NewBranches`, `UpdatedBranch`, `DeletedBranch`, `NewTags`

**Push:**
1. The current implementation returns input refspecs. Improve by noting which refs were actually pushed (though go-git doesn't expose per-ref push results easily — may need to accept the current behavior with a comment)

## Work Stream 4: Platform-Level API Gaps

### Task 4.1 — GitCode `CreateCommitStatus` (direct HTTP fallback)

**File:** `backends/gitcode/commits.go`

The gitcode_api SDK has no commit-status method. Implement using direct HTTP:
1. Use the SDK's internal HTTP client or build a raw HTTP call to `POST /repos/{owner}/{repo}/statuses/{sha}`
2. If the GitCode API genuinely doesn't support this endpoint, keep `ErrNotImplemented` with a clear doc comment

### Task 4.2 — GitCode `GetArchive` (direct HTTP fallback)

**File:** `backends/gitcode/releases.go`

The gitcode_api SDK has no archive download method. Implement using direct HTTP:
1. Call `GET /repos/{owner}/{repo}/archive/{ref}.{format}` via raw HTTP
2. If the GitCode API genuinely doesn't support this endpoint, keep `ErrNotImplemented` with a clear doc comment

### Task 4.3 — Gitee `CreateCommitStatus`

**File:** `backends/gitee/methods.go`

Gitee's public REST API does not expose a commit-status endpoint. This cannot be implemented. Keep `ErrNotImplemented` — no change needed.

### Task 4.4 — TencentCode `ProtectBranchOptions`

Fill in the `ProtectBranchOptions` struct with meaningful fields based on TencentCode's API:
- `MergeAccessLevel` (who can merge)
- `PushAccessLevel` (who can push)
- `AllowForcePush` (bool)
- `CodeOwnerApprovalRequired` (bool)

### Task 4.5 — `Repository.Close()` implementation

Implement cleanup logic:

- Log cleanup actions if a logger is available
- Return nil if nothing to clean up (graceful no-op)
